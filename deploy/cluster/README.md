# Расширение кластера Logister

Один файл `compose.yaml` описывает один узел Logister с API и веб-интерфейсом. Первый узел можно запустить вручную. Для нескольких хостов используйте Ansible, который разложит этот же файл и будет запускать узлы по одному с проверкой готовности.

Этот сценарий масштабирует слой приложения при готовом слое данных. Если новый физический хост должен также добавлять ёмкость или отказоустойчивость хранилищ, участники Kafka, MongoDB и OpenSearch присоединяются к существующим группам репликации по отдельным процедурам. После присоединения проверяется фактическое размещение копий. Ansible-роль Logister управляет API и UI.

## Интеграция с продакшеном

LDAP и Fluent Bit обслуживаются существующей инфраструктурой. Продакшен-узлы Logister запускаются через этот Compose или Ansible-роль.

- **LDAP**. Для новой установки войдите под резервным администратором и укажите адрес действующего каталога, учётную запись чтения и базы поиска в **Настройки LDAP**. Настройки хранятся в общей MongoDB. При добавлении API используйте ту же базу и тот же `AUTH_SETTINGS_KEY`. [Настройки LDAP](../../docs/roles.md#ldap-connection-settings)
- **Fluent Bit**. Используйте Kafka output действующего агента с адресами общих брокеров и топиком, который читает Logister. При расширении API используйте тот же топик и consumer group. Если агент уже пишет в этот топик, добавление узла не требует менять конфигурацию агента. [Схема доставки через Kafka](../../docs/kafka.md)

## Что должно быть готово

- Docker Engine и Compose v2 на каждом хосте. Образы API и UI должны быть доступны на всех хостах. Используйте один и тот же релиз из registry или загрузите образы локально. UI собирается с пустым `VITE_API_URL`, чтобы использовать прокси `/api/` на своём узле.
- Общие MongoDB в режиме replica set, OpenSearch и Kafka. Этот Compose разворачивает слой приложения в режиме Kafka Direct без Redis. При подключении узлов с других машин используйте адреса, доступные из их контейнеров. Для Kafka это также касается advertised listeners, для MongoDB replica set — адресов его членов.
- Одинаковые имя базы MongoDB, пространство индексов OpenSearch, Kafka topic и consumer group. Топик создаётся заранее. Чтобы все потребители одной группы могли получать работу, число партиций должно быть не меньше числа потребителей.
- Одинаковые пароль резервного администратора длиной 16–72 байта и 64-символьный hex-ключ `AUTH_SETTINGS_KEY`. Для существующей установки возьмите её ключ, которым зашифрованы настройки LDAP. Храните секреты в Vault или в файле с правами `0600`.

### Переход со старого HTTP-журнала

Переведите отправителей логов с HTTP на Kafka и остановите запись через HTTP. Пока работает старый API, дождитесь `pending_messages: 0` в `/api/health` при `redis: true`. После этого разверните новую сборку API и UI. Поиск и веб-интерфейс работают через HTTP как раньше. Маршруты HTTP-приёма событий в новом режиме возвращают `404`, а статистика приёма показывает Kafka Direct. Уже проиндексированные документы HTTP-журнала остаются доступны в поиске. Автоматическая ротация и очистка старых индексов HTTP-журнала приостановлены, поскольку новый режим не сверяет их с Redis. Политики хранения действуют для индексов Kafka Direct.

Если действующий кластер читает Kafka через Redis, сначала выполните [переход на Kafka Direct](../../docs/kafka.md#прямой-режим-kafka). Резервное копирование и вывод старого Redis из эксплуатации выполняются отдельно, после проверки очереди.

## Вручную

Команды выполняются из корня репозитория. Скопируйте пример и заполните адреса, образы и секреты.

```sh
cp deploy/cluster/.env.example deploy/cluster/.env.node-01
chmod 600 deploy/cluster/.env.node-01
docker compose --env-file deploy/cluster/.env.node-01 \
  -f deploy/cluster/compose.yaml -p logister-node-01 \
  up -d --wait --wait-timeout 180
```

На следующем хосте повторите запуск с `.env.node-02`, `LOGISTER_NODE_ID=node-02` и `-p logister-node-02`. Если запускаете несколько экземпляров на одном Docker-хосте, задайте каждому свой `LOGISTER_UI_PORT`. Уникальный `LOGISTER_NODE_ID` нужен для отображения экземпляра в мониторинге.

Проверка готовности запрашивает `/api/health` через UI и ждёт доступности MongoDB, OpenSearch и Kafka. После добавления узла проверьте его в разделе мониторинга и убедитесь, что у Kafka consumer group появились ожидаемые участники и распределены партиции. После штатного `docker compose … stop` узел исчезает из списка активных после истечения heartbeat, обычно в пределах 20–25 секунд.

Порт UI по умолчанию привязан к `127.0.0.1`. Для доступа через HTTPS настройте внешний прокси, укажите публичный `CORS_ORIGIN` и сохраните `AUTH_COOKIE_SECURE=true`. Для локальной проверки по HTTP укажите фактический origin и `AUTH_COOKIE_SECURE=false`. При балансировке веб-запросов включите привязку клиента к узлу, поскольку в этой версии курсоры поиска подписываются ключом процесса API.

## Через Ansible

Скопируйте `inventory.example.yml` в свой inventory, укажите доступные хосты и образы. В Vault передайте `logister_auth_local_password` и `logister_auth_settings_key`, а при необходимости и URL хранилищ с учётными данными. Роль предполагает, что Docker уже установлен, а пользователь, от которого запускается Compose, имеет доступ к registry и Docker daemon. Для запуска без sudo задайте `logister_become: false`. Для нестандартного Docker socket задайте `logister_docker_host`.

```sh
ansible-galaxy collection install -r deploy/cluster/ansible/requirements.yml
ansible-playbook -i /path/to/inventory.yml deploy/cluster/ansible/deploy.yml \
  -e @/path/to/logister-vault.yml --ask-vault-pass
```

Playbook проходит хосты в порядке inventory и останавливается при ошибке готовности. Чтобы добавить только один хост, допишите его в inventory и передайте `--limit node-04`. По умолчанию файлы узла находятся в `/opt/logister/<node-id>`. Повторный запуск приводит конфигурацию к тому же состоянию. [Модуль Compose для Ansible](https://docs.ansible.com/projects/ansible/latest/collections/community/docker/docker_compose_v2_module.html)
