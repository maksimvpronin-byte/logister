# Внутренний мониторинг

Откройте **Мониторинг** в меню администратора (`/#/monitoring`). Раздел и
`GET /api/monitoring` доступны только администратору. Проверка выполняется на
сервере при каждом запросе; скрытие кнопки не является механизмом защиты.
При отключённой авторизации endpoint закрыт (403).

## Что показывает страница

- Схему Kafka → Logister API → OpenSearch в режиме Kafka Direct. При включённом
  журнале Redis схема также показывает журнал и предвыборку внутри API.
  Пауза чтения находится на узле Kafka. Поиск, MongoDB, LDAP и приём по HTTP
  при включённом журнале показаны отдельными связями.
- Скорости уникального приёма и подтверждённой записи, объём исходного JSON
  и bulk-запросов. Дубликаты не увеличивают число уникальных принятых записей.
- Kafka lag, число и размер ожидающих сообщений Redis, возраст старейшего
  сообщения, заполнение журнала и объём тел в RAM-предвыборке.
- Последнее время и P95 разбора Kafka JSON, подготовки, приёма в журнал,
  bulk-запроса и доставки до ACK. P95 рассчитан по последним 128 операциям
  каждого этапа, а не по всем сообщениям за время работы. Для доставки одна
  операция — возраст старейшего сообщения подтверждённой порции.
- Ошибки bulk, отклонения 429, сбои публикации, дубликаты; предупреждения о
  росте очередей, заполнении журнала и нехватке диска OpenSearch.
- Действующие параметры обработчиков, буферов, размера bulk и новых индексов.

ACK означает подтверждение записи OpenSearch. Появление документа в поиске
зависит от отдельного refresh индекса. Это разные моменты времени.

Предупреждения о росте очереди оцениваются по изменению за 10 секунд: прирост
не меньше 100 сообщений и 10% начального размера очереди. Краткие пакетные
всплески не включают предупреждение. Состояние пересматривается раз в 10 секунд,
а при опустошении очереди снимается сразу. Пауза Kafka исключена из оценки роста.
Предупреждения стоят над остальной страницей. Длинный список прокручивается
внутри блока и не занимает пустую высоту, когда предупреждений нет.

## Сбор и ограничения

API собирает один общий снимок каждую секунду, параллельно опрашивая
компоненты с общим тайм-аутом 3 секунды. Открытие дополнительных вкладок и
кнопка обновления читают готовый снимок и не увеличивают частоту опроса
компонентов. Новые сервисы и доступ к Docker socket не требуются.

Таблица **Инстансы Logister** автоматически показывает активные API,
которые публикуют снимки в одну базу MongoDB. Для каждой реплики можно задать
уникальный стабильный `MONITORING_NODE_ID`. По умолчанию используется hostname.
Каждые 5 секунд API публикует статус и обновляет локальную копию списка.
Остановленный экземпляр исчезает из таблицы через 20 секунд после последнего снимка,
даже если локальная копия списка не обновилась. MongoDB удаляет записи старше
семи дней.

Статусы Kafka, Redis, OpenSearch и MongoDB в строке отражают доступность
сервиса из этого API. Они не означают, что на каждой ВМ запущена отдельная
копия сервиса. Графики показывают выбранный API, общие очереди Kafka
и Redis и его локальную историю за 15 минут. Перезапуск API сбрасывает
локальную историю. Общий экран открывается напрямую на любой реплике.

Источники ресурсов:

| Компонент | Доступные показатели |
|---|---|
| API | CPU и память своего контейнера из cgroup v2, Go heap, goroutine |
| Redis | CPU процесса, используемая память, RSS, AOF, ключи и журнал |
| OpenSearch | Суммарные CPU процессов, JVM heap, диски, шарды, очередь записи, отклонения |
| MongoDB | Размер данных, подключения и участники |
| Kafka | Lag, доступный и подтверждённый диапазон, состояние чтения |

CPU в ядрах: `1,0` означает одно полностью занятое ядро за интервал. Ресурсы
узла OpenSearch относятся к машине/VM, где он работает, а не обязательно к
физическому компьютеру пользователя. CPU/RAM процессов Kafka и MongoDB
недоступны через используемые интерфейсы. Отсутствующие или недоступные метрики показываются
прочерком/статусом недоступности, а не нулём. Снимок старше 15 секунд помечается
устаревшим. После 401/403 интерфейс удаляет ранее полученные данные.

Endpoint выдаёт только разрешённые метрики и параметры производительности,
без паролей, строк подключения и содержимого логов. Сбор метрик начинается
с входа Logister. Внешние сборщики, в том числе Fluent Bit, наблюдаются
в своей системе мониторинга.

## Проверки

`python3 deploy/tests/monitoring_live.py` проверяет запрет доступа, UI proxy,
кэширование снимков, очередь при остановленном OpenSearch и восстановление
доставки 2000 сообщений с текстом 5 КиБ. Скрипт использует локальный тестовый
стенд и удаляет созданные им синтетические данные после прогона.
