# Нагрузочная проверка трёхузлового стенда, 4 ноября 2026

В каждом прогоне один генератор отправлял в Kafka 200 000 уникальных событий с
текстом по 1 КиБ. API продолжал чтение во время отправки. Путь сообщения проходил
через Kafka, Redis и OpenSearch. Новый тестовый индекс имел два primary-шарда
и одну реплику на шард благодаря шаблону стенда. Результаты снимались раз в
секунду. Время доставки измерялось от запуска генератора до подтверждения
публикации всех сообщений и нулевого Kafka lag. Полноту поиска проверяли
отдельно после refresh.

Во всех четырёх прогонах генератор подтвердил 200 000 отправок, и поиск
вернул 200 000 документов. Ошибок bulk и отклонений записи не зарегистрировано.
Темп генерации и фоновое состояние Redis и OpenSearch различались между
прогонами. Таблица описывает время обработки всплеска на этом стенде.
Устойчивую пропускную способность и вклад каждого изменения отдельно не измеряли.

## Изменения

- Под нагрузкой журнал Redis упирался в лимит 256 МиБ. При сообщениях этого
  размера прежнее окно в 1 000 записей обычно превращалось в один bulk-запрос.
  Увеличили лимит окна до 4 000 записей при том же лимите 10 МиБ, чтобы
  два настроенных bulk-обработчика могли работать параллельно. Из ответов
  OpenSearch оставили статусы и ошибки, необходимые для проверки всей партии.
- В первом прогоне два API-узла сообщили о тайм-аутах, пока третий держал
  блокировку публикации. Теперь занятая блокировка возвращает управление
  рабочему циклу, который повторяет попытку через штатный интервал. Проверка
  владельца при подтверждении префикса очереди сохраняется.
- Первый прогон с изменениями прервался на HTTP 503 от /api/ingest/stats.
  Новый приём вклинился между отдельными чтениями счётчиков accepted и pending.
  Все 200 000 документов этой партии найдены в поиске. Счётчики теперь
  читаются в одной транзакции Redis. Оба полных контрольных прогона прошли
  без HTTP 503 и без тайм-аутов публикации.

Синтетические индексы и 1 000 000 подтверждённых записей журнала пяти прогонов
очищены, тестовые потоки архивированы. Обновлённый API работает на трёх
узлах стенда. На каждом Kafka lag и pending равны нулю, OpenSearch green.
Прошли go test ./..., проверка гонок для redisingest и search, go vet и
git diff --check.

Сырые измерения и сценарий прогона находятся в graphify-out/cluster-load.
Файлы baseline.json и baseline-repeat.json содержат исходные прогоны,
fixed-1.json и fixed-2.json содержат замеры окончательной версии,
optimized.json содержит проверку доставки партии с прерванным замером.
