# Нагрузочный прогон: полный текст 5 КиБ

Две партии по 100 000 сообщений. Текст — 5 120 байт, средний входной JSON с
метаданными — 5 295,78 байта. Полная индексация включена. Три поисковых образца
в каждом прогоне проверены на длину message ровно 5 120 байт.

Условия: Colima 8 vCPU/6 GB; один OpenSearch, heap 512 MiB; 2 primary shards,
replicas=0, zstd_no_dict/1; API workers=4, два bulk workers, RAM buffer 32 MiB.
Накопление Kafka перед чтением, автоматическое создание индекса, опрос 0,25 с.
Тайминги стадий включены на время теста, после него отключены.

| Прогон | Приём партии | Полная доставка | Скорость | Найдено |
|---|---:|---:|---:|---:|
| 1 | 6,599 с | 8,173 с | 12 235 логов/с | 100 000 |
| 2 | 5,874 с | 7,188 с | 13 912 логов/с | 100 000 |

В обоих запусках 0 ошибок bulk. Полная видимость в поиске подтверждена отдельно
через 31,04 и 30,84 с: refresh=30s. Это короткое опустошение очереди, не тест
длительной устойчивой нагрузки. Производственный код и его настройки не менялись.

Во втором запуске нагрузочная часть и проверка search_count завершились успешно,
но защитная проверка очистки увидела фоновые pending-сообщения. Обёртка research
завершилась с ошибкой именно на cleanup, поэтому её общий report содержит только
первый запуск; исходный report второго сохранён полностью. Очистка дополнена
ожиданием пустой очереди до 10 секунд и повторена для точного тестового потока:
удалены его индекс и 100 000 receipts. Первый прогон очищен автоматически.

В конце Kafka running/lag=0, pending=0, только пять обычных потоков,
диагностические флаги false. Компиляция cleanup-скрипта и git diff --check пройдены.
