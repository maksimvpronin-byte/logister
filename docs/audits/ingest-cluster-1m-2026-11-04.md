# Нагрузочная проверка трёхузлового стенда, 1 миллион событий по 10 КиБ

4 ноября 2026 года. Тракт Kafka → Redis → OpenSearch. Текст каждого
синтетического сообщения содержит 10 240 байт, Kafka JSON с метаданными
занимает около 10,4 кБ на событие. Тестовый топик имел шесть партиций и
три копии. Поисковый индекс имел одну реплику на шард. Для экономии диска
поколения тестового индекса ротировались. Каждое поколение после опустошения
очереди проверялось запросом OpenSearch _count по имени потока и удалялось
после сверки. Одновременное хранение миллиона документов не проверялось.

| Измерение | Документов | Время | Логов/с |
|---|---:|---:|---:|
| Исходная версия, контрольный прогон | 200 000 | 350,48 с | 571 |
| Исходная версия, участок 25 000–150 000 | 125 000 | 230,35 с | 543 |
| Исправленная версия, тот же участок | 125 000 | 163,33 с | 765 |
| Исправленная версия, до сигнала о потере retention | 787 027 | 1243,26 с | 633 |
| Заключительный этап после восстановления | 153 294 | 202,31 с | 758 |
| Полный прогон, включая восстановление | 1 000 000 | 1607,72 с | 622 |

Суммарно отправлено 1 003 294 уникальных события. До восстановления
отправлено 850 000, из них 846 706 дошли до поиска. Для итогового миллиона
отправили оставшиеся 150 000 и ещё 3 294 замещающих события такого же размера.
Все десять поколений по 100 000 документов подтверждены. Полный прогон
с исходными сообщениями без потерь не состоялся. Прямое сравнение скорости
выполнено на одинаковом участке двух прогонов. Результат включает совместное
действие нескольких изменений и различия в состоянии стенда.

## Узлы OpenSearch

Суммы взяты из размещения шардов при сверке каждого поколения. Скорость
по узлу включает основные и реплицированные копии за полное время прогона.
CPU — среднее число ядер, занятых процессом OpenSearch.

| Узел | Основных документов | Всего копий | Копий/с | CPU, ядра |
|---|---:|---:|---:|---:|
| lab-1 | 333 235 | 666 625 | 414,6 | 0,93 |
| lab-2 | 333 375 | 666 610 | 414,6 | 0,98 |
| lab-3 | 333 390 | 666 765 | 414,7 | 0,99 |

На исходной схеме доли индексаций по узлам составляли примерно 25%, 43% и 32%.
После перехода с двух на три основных шарда нагрузка распределилась
равномернее. Минимум свободного места во время полного прогона — 5,42 ГиБ.
По доступным снимкам ошибок bulk и отклонений записи не зарегистрировано.
API-счётчики по узлам сбрасывались при перезапусках во время восстановления.
Полные счётчики доставки получены из журнала Redis, а данные о копиях по узлам
из сверки шардов.

## Изменения и узкие места

- Добавлено сжатие объёмных тел Redis в Zstandard. В выборке из 500 реальных
  записей объём тел сократился с 10 485 563 до 2 810 521 байта, на 73,2%.
  Лимиты очереди и публикации считаются по исходному размеру, старые
  несжатые записи читаются. Начальные пробы Snappy и Zstd SpeedFastest дали
  меньший эффект на реальных документах. Итоговый код использует SpeedDefault.
- Redis выбирает префикс публикации по лимиту до передачи тел в API.
  На стенде размер bulk увеличен с 5 до 6 МиБ, чтобы окно 10 МиБ обычно
  помещалось в два запроса при двух обработчиках. Новые индексы стенда
  используют три основных шарда.
- Суммарный lag скрыл перекос партиций. В партиции 0 группа подтвердила
  смещение 193994, а Kafka уже хранила данные с 197288. Для продолжения
  увеличили лимит тестового топика с 192 до 384 МиБ на партицию и вручную
  передвинули только смещение тестовой группы для партиции 0 к началу
  доступного диапазона. Приложение само смещения не пропускает.
  API теперь отдаёт смещения и lag по партициям, мониторинг показывает
  максимальный lag. Генератор на заключительном этапе проверял каждую
  партицию перед новой партией. Пик lag одной партиции после возобновления
  составил 8 049. Новых потерь не зафиксировано.
- Логическая очередь Redis всё ещё достигала 256 МиБ. Приём мог опережать
  подтверждение в OpenSearch, даже когда средняя загрузка процесса Redis
  составляла около 0,29 ядра по медиане снимков. Дальнейший предел находится
  в тракте публикации. Замер не отделяет работу координатора bulk, ожидание
  подтверждений шардов и стоимость индексации.

Тестовые индексы и подтверждения журнала удалены, тестовый топик удалён.
Все три API возвращены к logister-ingest, lag и pending равны нулю,
OpenSearch green. Прошли go test ./..., проверка гонок для redisingest и
kafkainput, go vet ./... и git diff --check.

Сырые измерения, проверка поколений, подтверждения очистки и сценарии
прогона сохранены в graphify-out/cluster-load-1m.
