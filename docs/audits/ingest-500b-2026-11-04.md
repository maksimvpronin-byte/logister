# Полная индексация сообщений по 500 байт

В нагрузочных kafka_profile.py и ingest_research.py размер текста по умолчанию
снижен до 500 байт; параметр --bytes позволяет изменить его. Обёртка JSON и
метаданные идут сверх этого: среднее входное событие в этих запусках 675,78 байта.
Ограничения индексации или сохранения реальных логов не вводились. Текст целиком
индексируется; три образца в каждом прогоне проверены на длину ровно 500 байт.

Две отдельные партии по 100 000 сообщений, Kafka -> API -> Redis -> OpenSearch,
автоматическое создание индекса, 2 primary shards, один узел, zstd_no_dict/1,
workers=4, буфер RAM 32 MiB. Colima 8 vCPU/6 GB, OpenSearch heap 512 MiB.
Опрос раз в 0,25 с, диагностические тайминги включены только на время измерений.

| Прогон | Полная доставка | Скорость | Найдено |
|---|---:|---:|---:|
| 1 | 2,915 с | 34 308 логов/с | 100 000 |
| 2 | 2,882 с | 34 704 логов/с | 100 000 |

Обе партии полностью приняты и доставлены, ошибок bulk нет. Это короткие тесты
опустошения очереди, а не измерение длительной устойчивой скорости; при времени
около трёх секунд погрешность опроса существенна. Видимость всех документов в
поиске проверена отдельно, примерно через 30,6–30,7 с, согласно refresh=30s.

Тестовые данные после проверки удалены автоматически; отчёты сохранены.
В конце Kafka running/lag=0, pending=0, диагностические флаги false.
Python compilation и git diff --check пройдены. Производственный код не менялся.
